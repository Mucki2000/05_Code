# Lausebengel Rebrand: The Website Is a Phone

Date: 2026-09-24
Status: draft, awaiting review

## Goal

Replace the current dark editorial site with a playful retro concept. The
whole website is a green early-2000s toy QWERTY phone. The visitor switches it
on, watches it boot with a Brick-Breaker game, the camera zooms into the LCD,
and the LCD becomes the website: a BlackBerry-7290-style home screen with
pixel icons that open the content "apps".

## Non-goals

- No DE/EN split in the first version. One language, labels as given by the
  owner (HOME, SOCIAL, FILME, UNTERNEHMEN, WORK, CAREER, ABOUT).
- No water ring-toss game. Brick-Breaker only.
- No build tooling. Plain HTML, CSS, JavaScript, like the existing site.
- The old site is not deleted during development. See "Where it lives".

## Where it lives

- New files under `rebrand/`: `index.html`, `rebrand.css`, `rebrand.js`,
  `phone.png` (copy of the generated Higgsfield image) and `icons/` if any
  raster icons are needed later.
- Existing assets under `assets/`, `Logos/` are referenced with `../` paths;
  nothing is moved.
- Local preview: `python -m http.server 8000` from the repo root, page at
  `http://localhost:8000/rebrand/`. The old site stays reachable at
  `http://localhost:8000/`.
- Nothing is committed until the owner approves the look. On approval the
  `rebrand/` files move to the repo root and replace `index.html`,
  `current.html`, `about.html`, `de/`, `en/`.

## Assets

- `phone.png`: 1024 x 1536, green BlackBerry-style toy phone on pure black,
  screen off, "LAUSEBENGEL" on the case, pink letters on the top key row.
  Generated by the owner on 2026-09-24 and dropped into the repo root as
  `ChatGPT Image 24. Sept. 2026, 14_49_12.png`; it replaced the first
  Higgsfield photo (688 px wide, misspelled) during implementation.
  The photo is used only in the OFF, BOOT and ZOOM states. It must be
  swappable without code changes: the LCD position is defined once as
  percentages of the image.
- LCD area on the photo, as fraction of image width/height:
  left 0.139, top 0.207, width 0.712, height 0.297 (pixels 142,318 to
  870,773; aspect 1.6, close to 3:2). Measured with a script that walks
  outward from the screen centre until the green case starts. Stored as
  CSS custom properties on the phone element. Re-measure when the photo is
  replaced.
- The photo has a thin dark bezel around the LCD; the `#lcd` element
  overlaps it slightly so no seam shows in the zoom.
- Fonts from Google Fonts: "Press Start 2P" for labels and headings,
  "VT323" for body text. Both with monospace fallbacks.
- Pixel icons: seven inline SVGs, 16 x 16 grid, colourful 16-bit style like
  the BlackBerry reference (house, smartphone with play triangle,
  clapperboard, office building, film reel, briefcase, smiling face).
  Rendered with `shape-rendering: crispEdges` and `image-rendering: pixelated`.

## Visual language

Two palettes, one for the phone body and one for the LCD.

Phone (outside, OFF and BOOT):
- Page background pure black.
- Accent green `#8ec530` (sampled from the case) for the power button glow,
  loading bar and the frame in the ZOOM state.

LCD (inside, HOME and APPS), modelled on the BlackBerry 7290 screen:
- LCD background `#c7d2d6`, slightly blue-grey.
- Status bar and primary text navy `#1c2e5c`.
- Selection frame and active elements navy with a 2 px pixel border; hover
  uses the case green so the phone colour is still present inside.
- Bottom label bar shows the selected app name in navy, like "Messages"
  in the reference.
- A faint pixel grid overlay (2 px repeating pattern at low opacity) lies
  over the whole LCD, including images and videos, so photos read as LCD
  content.

## States and flow

The page is a single document. A root element `#phone` carries a
`data-state` attribute with one of `off`, `boot`, `zoom`, `home`, `app`.
CSS handles what is visible per state; JS only switches states and runs
the game.

### OFF

- Phone photo centred, height `min(92vh, 1024px)`, keeps aspect ratio.
- `#lcd` is an absolutely positioned div placed over the LCD area using the
  percentage custom properties. It is pitch black.
- In the centre of `#lcd` a pixel-art power symbol (circle with a gap and a
  vertical bar), green, with a soft glow (`filter: drop-shadow`) and a slow
  pulse animation. Cursor pointer. Keyboard: the whole `#lcd` is a button,
  Enter or Space also starts.
- Click starts BOOT.

### BOOT

- `#lcd` shows a `<canvas>` Brick-Breaker: six rows of bricks in red, orange,
  yellow, green, cyan, purple, a white ball, a white paddle, "SCORE n" top
  left, "n%" top right, a thin loading bar along the bottom edge.
- The game plays itself: the paddle tracks the ball with a small lag so it
  occasionally misses; a missed ball respawns. Moving the mouse over the LCD
  or pressing left/right arrows takes control of the paddle until the boot
  ends.
- The loading bar runs from 0 to 100 % in 6 s, eased so it stalls briefly
  around 64 % as a nod to the reference prompt. The percentage text is the
  same number.
- Clicking the loading bar or pressing Escape jumps to 100 %.
- At 100 % the game freezes for 300 ms, then ZOOM starts.

### ZOOM

- The phone photo and the LCD scale together (`transform: scale()` on a
  wrapper, transform-origin at the LCD centre) until the LCD fills the
  viewport, over 900 ms with an ease-in-out curve.
- During the zoom the LCD content already switches to the HOME screen, so
  the visitor zooms into the home screen, not into the game.
- When the transition ends the photo is hidden and the layout switches to
  the "inside" layout: `#lcd` becomes `position: fixed; inset: 0`
  surrounded by a green frame (`border: clamp(6px, 1.2vw, 14px) solid`
  case green) with the Lausebengel wordmark image small in the bottom
  frame. This frame is drawn with CSS, not with the photo, so it stays
  sharp at any size.

### HOME

Layout inside the LCD, top to bottom:
- Status bar, navy on LCD grey: left "LAUSEBENGEL" in Press Start 2P, centre
  weekday, date and current local time (updated every minute), right signal
  bars and "GPRS".
- Icon grid: four icons in the first row, three centred in the second row,
  each with its label underneath in Press Start 2P at small size. The first
  icon starts selected with a navy frame.
- Bottom label bar: the selected app name, centred, navy.
- Interaction: click opens an app. Hover selects. Arrow keys move the
  selection, Enter opens. Keyboard support is a bonus, the mouse is the
  primary input.

### APP

- Opening an app slides the app screen in from the right over 200 ms; back
  slides it out. Only one app is open at a time.
- Every app screen has the same status bar, a title bar with the app name and
  a "< BACK" button on the left, and a scrollable content area. Escape and
  the browser back button also go back (history API with a hash per app,
  `#social` etc., so app screens are linkable).
- Content components, all in LCD style:
  - Project tile: image or video in a navy 2 px frame with the pixel grid
    overlay, caption below in VT323 with client and title. Videos use the
    same hover-to-play behaviour as the old site where a video exists.
  - Text block: VT323, navy, max width about 60 characters.
  - Crew card: circular photo, sticker image underneath, as on the old
    about page, but inside the LCD frame.
  - Logo strip: the existing client logos, converted to navy via CSS filter.

### Return visits

`sessionStorage` key `lb-booted`. When set, the page opens directly in the
HOME state without photo, boot or zoom. Deep links (`#filme`) open that app
directly, also skipping the boot.

## Responsive behaviour

- OFF and BOOT: the portrait photo fits within the viewport height on
  desktop and within the viewport width on phones (`max-width: 94vw`).
- Inside: the LCD is the viewport. On narrow screens the icon grid becomes
  two columns, project tiles stack, the status bar drops the date and keeps
  the time.
- Everything scales in relative units; no horizontal scrolling.

## Accessibility

- The power button and all icons are real `<button>` or `<a>` elements with
  labels.
- `prefers-reduced-motion`: no pulse, zoom is a 150 ms crossfade, the game
  still runs but the loading bar completes in 1.5 s.
- Text contrast navy on LCD grey passes AA.

## Error handling

- If `phone.png` fails to load, a CSS-drawn green rounded rectangle with a
  black screen is shown instead, so the site still works.
- If a video is missing, the tile shows the still image or a text
  placeholder, as the old site does.
- If `canvas` is unavailable, BOOT shows only the loading bar.
